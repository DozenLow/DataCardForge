## 一、字符画全部改成 SVG

`docs/` 与根 README 里曾有 6 处靠**字符等宽对齐**画出来的示意图（决策流向图、端口投影树、架构图）。问题不在丑，在于它把结构信息编码进了"第几列"：换一个字体、换一个渲染宽度、在手机上看，图就散了；而它携带的信息（谁依赖谁、哪条边跨层）是最需要读对的部分。

现在改成 6 张 SVG，中英各一对（`decision-flow` / `port-projection` / `architecture`），见 [`diagrams/`](../diagrams/)。根 README 的架构段与 `docs/` 复用同一对，避免两份图各自漂移。

技术上的几个决定：

- 纯 SVG：无 `<script>`、无 `<foreignObject>`、不引外部字体——GitHub 用 camo 代理、Obsidian 直接渲染，任何"运行时依赖"都会在其中一种路径上失效；
- 颜色走 CSS 变量 + `@media (prefers-color-scheme: dark)`：作为 `<img>` 引用时也能跟深色主题走；
- 文字仍是 `<text>`：可选中、可检索、能被辅助技术读到，不是把整张图烤成一张位图。

另附 [`interactive.html`](../diagrams/interactive.html)：点选阶段/组件看它当时的判断与出处，可切中英与主题。它是阅读增件，不是权威内容；`file://` 直接打开会退化成静态图（点选需要 http）。

## 三、护栏

[`scripts/docs-check.py`](../../scripts/docs-check.py) + CI 里一个独立 job，检查六件事：导航覆盖（git 追踪的每篇 docs 文档都要能从导航链到）、死链、字符画残留、图的孤儿引用、中英配对、SVG 合法性（`viewBox`/`title`/`desc`、无 script、无外链）。

没并进 `vitest`：那是测试面，会动 594 这个口径。这条可整条 revert 而不影响别处。

故意注入了死链、框线字符、孤儿图各一处，确认它真的会红——**不会失败的闸门等于没有闸门**。

## 教训

1. **文档的不一致不会自己报错**。能机械判定的（链接、配对、格式）交给脚本；判不了的（一句话里的代号还有没有指代对象）至少写成规则，并在评审时问一句"一年后的人能懂吗"。
2. **补丁会累积成结构**。同一个文件被追加三四轮"补充""复核"之后，读者要读的是修订史而不是内容；该重写就重写，把过程性内容挪进 `log/`。
