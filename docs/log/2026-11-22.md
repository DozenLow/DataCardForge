## 一、bug：BFS 距离不是求值序

`collectSubtree` 沿 `dependents_` 做 BFS，注释曾声称"边从源指向依赖者，所以这个序已经是依赖优先"。这个断言对**链**成立，对**不等长路径的汇聚点**不成立：BFS 距离是变更点到节点的**最短**路径，而一个汇聚节点必须等它**最长**的那条上游路径走完。

现场复现（独立后端实例，HTTP 层）：源表 10 行，`A=a*2 -> B=A+1 -> C=B*B -> Z=C+1`（深 4），拟合卡 `D=fit(x=A, y=Z)` 汇聚深 1 与深 4。PATCH 源表第一格 3->7 后：

- 一波结束的 D（状态 `done`，绿灯）：slope **24.236453**、intercept **-117.684729**；
- 单独重算 D（上游全新鲜）：slope **25.832512**、intercept **-115.556650**；
- 反算证实波里那组数恰为 `fit(x_new, z_old)`：**A 用了新值、Z 用了旧值，混算后盖 done**。

触发条件：下游节点有 >=2 个输入且上游路径不等长。拟合卡（`builtin:linear-regression`，双端口、非惰性）今天即可触发；脚本卡多输入暂时安全只因为它是惰性签名（一波只打脏并剪枝下游）——一旦改成并行调度，这层偶然保护就消失。这正是 2026-10-18 审计要消灭的"下游读旧数"类缺陷，从 BFS 序这个入口又进来了。

## 二、修复：waveOrder（诱导子图 Kahn）

- `collectSubtree` 保留为**波集合**查询（BFS 可达性），注释改为明说"访问序不是求值序"；惰性剪枝仍用它。
- 新增 `NodeRegistry::waveOrder`：对波集合做 Kahn 拓扑排序。波内前驱从 `dependencies_` 解析——正键是节点 id，负键（矩阵 mid-edge）经 `resultOwner_` 解析到生产者（覆盖结果矩阵与脚本额外输出，两者创建时即登记）；同一生产者的多个端口**去重为一条就绪依赖**。
- 就绪集按节点 id 取最小，**一波的序列确定可复现**（事件序、黄金夹具稳定）。
- `recomputeSubtree` / `computeNow` 改走 `waveOrder`；`evaluateInOrder` 的惰性剪枝逻辑不变（拓扑序下惰性节点的全部下游必然排在其后，剪枝只会更稳）。
- 求值仍是串行、锁策略不变。图由 `wouldCycle` 保证无环，Kahn 必然吐尽整波；防御分支把残余按 id 追加——错序可见于数值，漏算不可见。
