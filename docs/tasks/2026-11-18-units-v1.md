# 任务书：单位 v1 —— 可见 → 可换算 → 提示

- **日期**：2026-11-18
- **状态**：📝 计划中（P0 口径待确认；**尚未改任何代码**）
- **上游决策**：待写 `docs/decisions/2026-11-18-units-v1.md`（P0，口径见 §六）
- **一句话**：把单位从"表头字符串"变成"结构化列元数据"——先让它**可见**（表头/轴/导出），
  再让**换算显式一键**，最后让**加法类错配可见**；数值永不自动改写。

## 〇、与既有决策的关系

- 不回退「后端持有计算」（2026-10-17）：换算在 C++ 后端算，前端不算数。
- 「卡是函数」：换算卡是普通签名（1 进 1 出），产出新表，源表不动。
- **不碰** DCM2 帧、表达式语义、参数表单缺口——换算卡用专用 UI（照 `SummaryPanel` 的模式）。
- 与「表永不改写 / 一切处理产出新卡片」一致；与脚本卡「标注而不拦截」的哲学一致。

## 二、不变量（P0 决策要写死）

| # | 不变量 | 理由 |
|---|---|---|
| 1 | **数值永不自动改写**；换算只产出新表 | 「表永不改写」+ 可复现 |
| 2 | **`annotation` 原文不动**，单位是它的解析附注 | 表达式按原文引用（`[压力_MPa]`），改了会破公式 |
| 3 | **显示的数字与显示的单位同源** | 只改一边 = 1000× 误读 |
| 4 | **单位不进 DCM2 帧** | 帧长 `24+rows*cols*8+namesLen` 无扩展位；单位在卡层，计算时随 `params` 下行 |
| 5 | **不做量纲代数**（`* / ^`） | 跨层 oracle 冻结；工程/科学会用温度²，不能拦 |
| 6 | **非标量单位只做标签**（°C/°F/pH/dB/HRC…） | 无乘性换算；只允许同单位加减 |

## 三、识别规则（P0 决策候选）

- **语法**：`<量名>_<单位token>`；token 内部 `_` 表除法（`vibration_mm_s` → mm/s）。
  复合单位（`kwh_m2`、`ugm3`、`wm2`、`mg_l`、`umol_min`）**只走目录条目**，不做语法合成。
- **匹配顺序**：最长后缀 → 精确大小写 → 唯一大小写折叠 → 三态。
  例：`Nm`（N·m）与 `nm`（nm）、`kW` 与 `kw` 靠精确匹配区分。
- **三态**：`recognized`（chip 实心）/ `ambiguous`（虚线圈 + 候选）/ `unknown`（不显示）。
- **单字符一律 `ambiguous`**：防 `sensor_a..j`、`group_a..d` 被识别成 A/d/g/h。
- **数字结尾不算单位**：`ch_001`、`batch_1`、`x1`、`c1`。
- **歧义清单 v1**（同形异义，必须用户确认）：`ms`（毫秒 / m·s⁻¹）、`mm`（毫米 / mM）、
  `mw`（mW / MW）、`m`（米 / 毫?）、`a`/`c`/`g`/`d`/`h` 等单字符、`ph` 是 pH 还是"phase"。
- **排除（只标签，不换算）**：`℃`/`°C`、`°F`、`pH`、`dB`、`dBm`、`HRC`/`HV`/`HB`、`au`（任意单位）。
- **确认是组级的**（用户口径 2026-11-18）：同一矩阵卡内同 token 一次确认，确认前列出受影响的
  全部列；结果按**列单位签名**记忆，同一签名再次出现不再询问。详见
  [决策 §三](../decisions/2026-11-18-units-v1.md)。
- **v1 目录种子**（取自 `work/DataCardForge-demo-data` 的 54 份表头实测，见附录）。

#### P2 契约细化（已锁定，judge 已写好，实现必须让它变绿）

- **judge 先行**：`web/tests/fixtures/cards/function-card.v2.json` 已由 lead 追加 9 条
  `unit-convert-*` 用例（期望值用独立 oracle 按锁定公式算出，**exact double** 比对）。实现不得改这些期望值。
- **签名**：`builtin:unit-convert`，1 矩阵输入端口 `src` → 1 输出 `result`，K=1，`explicitCompute=true`
  （创建不算，`POST /api/nodes/{id}/compute` 才算；照 `builtin:summary`）。
- **params**：`{ targets:[{ column:<0-based 列号>, from?:<单位串>, to:<单位串> }] }`。
  `targets` 缺失/空/非法 → `badSignatureParams`。
- **输出形状**：输出 = 整张输入表；被 target 命中的列做换算，其余列**原样透传**（值与 annotation 都不动）。
  列数 = 输入列数。透传列**不要求**单位可解析（未确认的 `temp_c` 也能透传）。
- **换算公式（锁死运算顺序）**：`out = value * factorFrom / factorTo`，逐值、从左到右两次运算；
  **不得**先算 `factorFrom/factorTo` 再乘，**不得**开 fast-math。factor 常量与 `web/src/core/units.ts` 完全一致
  （`rpm = 1.0/60.0`）。这是 exact-double 夹具能过的唯一方式。
- **from 解析**：给了 `from` → 查注册表（须已注册且 scalar）；没给 → 用 C++ 解析器解析该列 annotation。
  结果须 `recognized` 且 scalar，否则报错（见下）。`from` 显式给出可**绕过** annotation 的 ambiguous。
- **annotation 重写**：命中列的输出 annotation = 把解析出的单位 span 替换为 `to` 的**规范串**
  （如 `pressure_kpa`→`pressure_bar`、`wind_m_s`→`wind_mm/s`）；annotation 无单位 span 但给了 from 时，追加 `_`+`to`。
- **错误码**（结构化，绝不静默换算）：
  `unitMismatch{column,from,to}`（量纲不同）· `unitNotScalar{column,unit}`（°C/dB 等非标量）·
  `unitAmbiguous{column,token}`（from 缺省且 annotation 歧义）· `unitUnknown{column}`（from 缺省且无单位）·
  `unknownUnit{unit}`（from/to 不在注册表）。
- **注册表跨层一致**：`backend/src/units.h/.cpp` 是 `units.ts` 的逐语义移植，必须通过
  `web/tests/fixtures/units/parse.json` 全部用例（`backend/tests/units_test.cpp` 读同一份 JSON）。
- **TS 裁判**：`web/tests/cardFixtures.test.ts` 的 `DECLARED_PORTS` 加 `'builtin:unit-convert':['src']`，
  并让其不变量逻辑接纳该签名（输出列数=输入列数、`trigger:'compute'`、lazy `afterCreate`）。TS 侧不算数值。

## 六、已拍板口径（2026-11-18）

1. **单字符单位**（`s`/`m`/`g`/`A`/`°C`）一律 `ambiguous`，需一次确认。✅ 采纳
2. **同形异义 token**（`ms` 毫秒 vs m/s、`mm` 毫米 vs mM、`mw` mW vs MW、`ph`）一律待确认。✅ 采纳
3. **P1 只加 chip、不改现有列名显示**（避免 `pressure_kpa (kPa)` 重复）；列名改写只发生在
   P2 换算卡的输出列。✅ 采纳
4. **确认是组级的**：同一矩阵卡内同 token 一次确认（确认前列出受影响的全部列）；
   按列单位签名记忆，**同一签名的多个矩阵不再重复确认**。✅ 采纳（本阶段严格执行，
   放宽到"默认值"是另一次决策，见决策文档 §六）
