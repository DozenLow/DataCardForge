# 决策：单位 v1 —— 列元数据、三态识别、组级确认

- **日期**：2026-11-18
- **状态**：🔒 已定稿（P1 实施中；放宽口径是**另一次**决策，见 §六）
- **标签**：`#数据卡 #函数卡 #列元数据 #单位 #契约`
- **配套文档**：[任务书](../tasks/2026-11-18-units-v1.md)、
  [后端协议 v1](../architecture/backend-protocol-v1.md)、
  [函数卡的三个契约](./2026-10-27-card-contracts.md)
- **结论**：单位是列的**解析附注**，不是数值变换。识别结果分三态
  （`recognized` / `ambiguous` / `unknown`）；**单字符与同形异义一律 `ambiguous`**，必须由用户确认；
  确认是**组级**的（同一矩阵卡内同 token 一次确认，确认前列出受影响的全部列），并按
  **矩阵的列单位签名**记忆——同一签名再次出现（重开同一文件、另一张卡读同一文件）不再询问。
  换算只做显式、1 进 1 出、产出新表；数值永不自动改写；不做量纲代数；单位不进 DCM2 帧。

## 一、为什么"标注"而不是"自动换算"

三条既有约束同向：

1. **表永不改写**——入库归一化（把 MPa 列全改成 Pa）直接改写源数据，违反卡片模型。
2. **数字与单位必须同源**——只改一边就是 1000× 误读。自动换算不能只改数字，连标签一起改
   就是静默改写用户数据。
3. **可复现**——同一文件在不同版本下算出的数必须一致；换算策略变一次，"换文件自动重算"
   的语义就全乱。

推论：自动化的甜区是**读**（识别、比对、算因子、派生标签），不是**写**（改数值）。
这也是本项目对脚本卡"标注而不拦截"的同一哲学。

## 二、语法与识别

- **语法**：`<量名>_<单位token>`。token 内部 `_` 表除法（`vibration_mm_s` → `mm/s`）。
- **复合单位只走目录条目**：`kwh_m2`、`ugm3`、`wm2`、`mg_l`、`umol_min`、`l_min` **不做语法合成**，
  按最长后缀整段匹配。
- **匹配顺序**：最长后缀 → 精确大小写 → 唯一大小写折叠 → 三态。
  例：`Nm`（N·m）与 `nm`（nm）、`kW` 与 `kw` 靠精确匹配区分。
- **三态**：
  | 态 | 含义 | 显示 |
  |---|---|---|
  | `recognized` | 目录命中且无歧义 | 实心 chip |
  | `ambiguous` | 命中歧义/单字符，等用户确认 | 虚线圈 + `?` |
  | `unknown` | 不是单位 | 不显示 |
- **单字符一律 `ambiguous`**：`s`/`m`/`g`/`A`/`C`/`d`/`h`/`J`/`F`/`H`。
  否则 `sensor_a..j`、`group_a..d` 会被识别成安培/天/克。
- **数字结尾不算单位**：`ch_001`、`batch_1`、`x1`、`c1`。
- **数量词不算单位**：`id`、`no`、`units`、`qty`。
- **v1 目录种子**取自 `work/DataCardForge-demo-data` 的 54 份表头实测（见任务书附录），
  目录条目 = `{token, 量纲, 到 SI 的因子}`；`pct`=1e-2、`ppm`=1e-6、`ppb`=1e-9 也是条目。

### 歧义清单 v1（必须确认）

`ms`（毫秒 / m·s⁻¹）、`mm`（毫米 / mM）、`mw`（mW / MW）、`ph`（pH / phase）、
所有单字符 token。

### 非标量（只做标签，不换算、不参与代数）

`℃`/`°C`/`c`、`°F`、`pH`、`dB`、`dBm`、`HRC`/`HV`/`HB`（经验标度）、`au`（任意单位）。
理由：仿射（°C/°F）、对数（pH/dB）、经验（HRC）三类没有乘性换算；工程与科学都会在
数值上用它们做平方/比值，系统不拦，但也**不声称**结果是物理量。

## 三、确认语义（本决策的核心）

- **组级**：确认的目标是**同一矩阵卡内同一 token**（大小写折叠后）的全部列。
  一次动作覆盖本卡所有同 token 列，不再逐列问。
- **先看后果**：确认前弹出"将把下列 N 列确认为 `<单位>`：`current_a`, `cell_current_a`, …"，
  列出完整清单；可取消。这是组级确认的安全阀——批量永远可见。
- **记忆**：确认结果写入工作区，键 = **矩阵的列单位签名**（按列序的 `annotation` 序列，
  确定性哈希）+ 列索引。同一签名再次出现时直接套用，**不再询问**。这正是
  "多个同样列向量组单位签名的矩阵不再重复确认"的实现口径。
- **单列覆盖**：任何列仍可单独改/清除（列头菜单）。覆盖写入同一记忆，作用于该签名该列。
- **持久化**：确认记忆随工作区快照保存（可选字段，不升 `version`）；矩阵本身**不存** `unit`
  字段——单位永远由 `annotation` + 确认记忆**派生**，避免快照与数据不一致。

## 四、换算语义（P2）

- `builtin:unit-convert`：1 输入端口 → 1 输出端口，K = 1；`params.targets:[{column, from?, to}]`。
- 换算必须**显式**：用户选目标单位、点"换算"，产出一张新表；源表与源数值不动。
- `from` 缺省由后端按同一目录解析 `annotation` 得到；用户的确认/覆盖以 `from` 显式下行。
- 同量纲校验：量纲不等 → 结构化错误 `unitMismatch{column, from, to}`（**绝不**静默换算）。
- 非标量与 `ambiguous` → 拒绝（`unitNotScalar` / `unitAmbiguous`）。
- 输出列的 `annotation` 用 `to` 重写单位后缀（例如 `地面速度_μm/s` → `地面速度_mm/s`）。
- 专用 UI（照 `SummaryPanel`），不依赖尚未实现的「按签名渲染参数表单」。

## 五、不做清单（v1）

- 自动改数值 / 入库归一化 / 轴自动换单位。
- 量纲代数（`* / ^` 的幂次追踪）——见 §六 与 [任务书] 的风险表。
- 单位进 DCM2 帧（`24+rows*cols*8+namesLen` 没有扩展位）。
- °C/°F/pH/dB 的语义处理。
- 表达式内的单位检查（P3 另开，且只加提示、不改数值）。

> 上述「不做」的前向规划（P3 提示 + 公式输出单位 + 量纲推断阶梯 L1→L3）见草案
> [单位感知阶梯](./2026-11-19-units-awareness-p3-and-formula-output.md)（📝 讨论中、未实施）。
> 公式卡输出丢单位是该范围的直接推论：对复合表达式是诚实，对保单位变换是过宽——草案以「只声明能证明的」逐级补齐。

## 六、为什么"待确认"是阶段性的

用户口径（2026-11-18）：**本阶段严格执行"单字符与同形异义一律待确认"，后续再考虑放宽**。
放宽（例如按量化默认）不是改一个开关，而是一次新决策：
它改变"系统是否替用户下结论"这条边界，必须重新论证 §一 的三条约束。

## 七、已知盲区（写下来，不解决）

- 同一 token 在不同语境含义不同（`ms`：`time_ms` 是毫秒、`wind_ms` 是 m/s）——
  组级确认以"同一张卡"为界，跨卡同 token 不共享结论。
- 列单位签名相同但语义不同（两份文件都叫 `a` 但一个是安培一个是索引）——签名相同即视为同一
  数据来源的同一列，这是"不再重复确认"的代价，接受。
- 表头解析永远有假阳性可能；`ambiguous` 态是唯一防线，所以**不放宽单字符**是 v1 的硬边界。

## 八、验收信号

- `web/tests/units.test.ts` 覆盖三态、大小写、复合后缀、数字结尾、数量词、非标量；
  用例同时被 C++ `backend/tests/units_test.cpp` 读同一份 `web/tests/fixtures/units/parse.json`。
- 组级确认：同一卡 10 列同 token，一次确认全部生效；清单一栏可核对。
- 记忆：同一文件重建卡片/重开工作区后不再询问（快照往返测试）。
- 人工：`sensor_a..j` 不得 `recognized`；`current_a` 一次确认后 `cell_temp_c` 仍需各自确认
  （不同 token）。
- P2：`ctest` 全绿；µm/s→mm/s、MPa→bar、rpm→Hz、ppm→ppb 正例；MPa→kN、dB→Pa、`mw` 拒绝。
