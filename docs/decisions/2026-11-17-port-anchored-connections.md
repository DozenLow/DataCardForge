# 决策：连线端点落在端口子卡片：端口优先、缺端口回退朝向卡边

- **日期**：2026-11-17
- **状态**：✅ 已实施（端口子卡片边中点锚点、来源输出按本地 matrixId 反查、侧法向贝塞尔、脚本卡三栏与端口注册）
- **标签**：`#前端 #连线 #端口 #布局`
- **结论**：一条依赖边的两端，落在这条边所绑定的**端口子卡片靠窗口一侧的边中点**上；
  端口没有被渲染时回退到朝向对方的卡边。来源侧的输出不由边携带，而是按目标输入指着的
  本地 `matrixId` 反查发布它的输出。一对卡仍然只有一条线（多端口取锚点均值）。
- **上游决策**：[连线从属原则](2026-08-07-connection-subordination.md)、
  [端口级连线](2026-10-28-port-level-connections.md)（本决策恢复其决策 3，改为端口边中点）、
  [卡心端点](2026-10-29-connection-center-anchors.md)（本决策取代其决策 1 与不变量 2）

## 核心表述

> 线从哪里进出，就该看得出来：输入的线在输入小卡片的左侧边中点接上，输出的线在输出
> 小卡片的右侧边中点离开，高度是那一行的高度；没有渲染端口的卡，才退回朝向对方的卡边。
> `portId` 仍是身份，位置只是这个身份今天恰好占着的那块几何。

## 背景（这一轮修的是什么）

2026-10-29 把端点钉在两张卡片窗口的中心，卡内的那一段交给遮罩吞掉。那解决了「线总是从
右侧中部挤出、被拽成一束」的问题，但也带来了新的代价：

| 现象 | 原因 |
|---|---|
| 一条线看不出连的是哪个端口 | 端点固定是卡心，`in:0` 与 `in:1` 的线完全重合 |
| 脚本卡有 K 个声明输出（`out:N`）之后尤其明显 | 卡心端点与「输出行」没有关系，右键建卡/接线时只能靠标签猜 |
| 端口行是卡片的一部分，却没有任何几何表达 | 端口只是数据身份，线的可见段从卡片边框开始，跟行高无关 |

同一时期脚本卡从「上下堆叠」改成「左输入栏 / 中间代码 / 右输出栏」，输入与输出第一次
成为真正的**子卡片**（每行一张小卡片）。用户的要求是：连线的起终点不再是卡片中心，而是
被连接的输入/输出子卡片靠近窗口一侧的锚点。

## 决策内容

1. **端点两级解析**。先端口，再卡边：
   - 目标侧：边本身携带端口身份（`edge.ports` 是依赖方的 `portId`），把这个 id 交给
     `cardMetrics.portAnchor` 测量；
   - 来源侧：边不携带输出身份，改用目标输入的 `target.matrixId` 在
     `publishedMatrices(sourceCard)` 里反查 `outputId`（`out:1` / `result` / …）。
     「序号 0 就是 `displayMatrixId`」这条例外只由 store 拥有，本决策不复制它；
   - 反查失败、端口不存在或未注册时，该端回退到卡边（见第 3 条），绝不猜一个输出。

2. **锚点 = 端口子卡片窗口侧边的中点**。`portAnchor` 由「元素中心」改为按注册的 `side`
   取边中点：`left → 元素左边`、`right → 元素右边`、`top → 上边`、`bottom → 下边`。
   子卡片本身是行卡片里的「行头」（名称、来源、形状那一行），所以展开输出预览不会把锚点
   拉下去。测量结果再夹进所属卡片的矩形：行被滚动出面板时元素可能报告到卡外，锚点跑到卡外
   会让线凭空出现。

3. **缺端口回退**（确定性两遍解析）：
   - 只有一端有端口：另一端取朝向对方的卡边，坐标用对方的锚点坐标，并夹进本卡跨度内缩
     8px（横边夹 y、竖边夹 x），于是线一直平到边框；
   - 两端都没有端口（数据卡 → 图表卡等）：各自取两卡中心连线决定的面朝边的中点，与
     2026-10-28 的「朝向对方的卡片边缘」一致；
   - 所有测量锚点再按本卡矩形夹一次。

4. **多端口取均值**。同一条边可能携带同一张卡的多个端口（一张表喂三列给同一张图）。
   锚点取这些端口的算术平均，仍然只有一条线——「一对卡一条线」是冻结契约，不按端口扇出。

5. **侧法向贝塞尔**。`wireGeometry(from, to, fromSide, toSide)`：两个控制点沿各自边的外法向
   生长，长度取两端距离的一半（上限 400 平面 px）。横排同高退化成直线；竖直/斜向是 S 形；
   两侧都朝外（目标在源左侧）时得到对称回环。**不传 sides 时保留 10-29 的「水平解/垂直解
   按 |dx| 加权混合」**，所以纯几何函数的旧用例逐字节不变。

6. **遮罩、箭头、标签、绕行、补间、流动虚线全部不动**。箭头仍沿曲线二分停到目标卡边框外，
   区别只是它现在落在端口行的高度上；卡片内的那一小段（约 6–8px）继续由遮罩抹掉。

7. **脚本卡的三栏是这条决策的布局面**：输入栏在左、编辑器在中、输出栏在右；每行的「行头」
   注册为端口（输入 `left`，输出 `right`），预览与删除按钮留在行头之外。`CardShell` 增加
   可选的 `minWidth`/`minHeight`（脚本卡 520×320），因为三栏在 280px 下会把编辑器挤没。

8. **测量要新鲜**。端口注册用稳定的 ref 回调（脚本卡每次按键都重渲染，回调不稳定会变成
   每个字符一次注册）；面板滚动、行列表尺寸变化（预览展开、改名提示换行）、增删端口都会
   触发 `invalidateLayout()`，连接层按现有 1 帧节流重新测量。

## 不变量（改这块时不许破）

- 一对卡一条线；多端口只平均锚点，不扇出成多条线。
- 只有**被渲染**的端口才是锚点；身份永远是 `portId`，几何不得反向定义身份（不做位置语义）。
- 缺端口时回退到朝向对方的卡边；不得根据位置去推断某个端口「应该是」连的。
- 未被挡住时路径是单条三次贝塞尔；绕行、拐点预算（≤ 2）、张力选择与 10-29 一致。
- 箭头尖必须在目标卡片边框之外；整条线被目标卡吞掉时不画箭头。
- 连线层永不拦截指针（`pointer-events: none`）、永不参与布局。
- 灰色未选中线不流动；红/蓝仍是长/短流动虚线（颜色 + 图案 + 流向三重编码）。
- 端口测量只按 `portId` 查注册表，不按位置查。

## 已知代价（下一轮）

- **反向布局会绕卡**。输出物理上永远在卡片右侧、输入永远在左侧；目标在源左侧时线只能从
  右侧离开再绕回来，途中可能被自己的卡片遮住一段。这是「端口是物理位置」的直接代价，不为此
  引入第三方求解器。
- **滚动的测量时机**。端口被滚动出面板时锚点被夹到卡边；面板滚动与行列表尺寸变化会触发重测，
  但页面级的缩放/字体变化仍依赖下一帧的失效。
- 端口圆点（08-07 的「端口标记兜底」）仍未做：现在线本身已经说明了端口位置。
- 没有按端口扇出，也没有 hover / 断线编辑——两者都要动「连线不拦截鼠标」这条锁定项。
- 页面级 `prefers-reduced-motion` 只影响补间，不影响侧法向形状。
