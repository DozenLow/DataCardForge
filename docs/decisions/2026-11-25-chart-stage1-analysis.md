# 决策：绘图卡第一阶段采用后端分析节点，分类文本不进入 DCM2

- **日期**：2026-11-25
- **状态**：🔒 已定稿
- **标签**：`#图表 #数值计算 #分类数据 #协议`
- **配套文档**：[后端拥有计算](./2026-10-17-backend-owns-compute.md)、
  [后端协议 v1](../architecture/backend-protocol-v1.md)
- **范围**：只支持“临时看一下数据”的绘图、标注、派生量与诊断；不引入可重放脚本、
  血缘、审计、撤销、SPC 判定或出版级规范。

## 结论

1. 绘图卡继续是浏览器里的一个普通卡片，不新增公开函数卡或表达式入口。
2. 新增生产数值计算一律通过后端隐藏分析节点完成。图卡只发送绑定与有限下拉参数，
   读取结果矩阵后交给 ECharts 渲染。`POST /api/nodes/{id}/compute` 的同步语义不变。
3. `builtin:chart-analysis` 是图卡专用签名，但仍使用普通节点协议、状态机与结果矩阵。
   参数只允许有限枚举和数值边界；签名输出统计表与逐点诊断表。拟合失败、奇异、
   非正 log 输入、非均匀采样等情况返回结构化错误，不输出看似合理的数据。
4. 现有浏览器 `stats.ts` / `Smoothing.ts` 冻结为参考实现；本决策不在前端新增
   回归、区间、非线性拟合、LOD/LOQ 或滤波算法。抽稀、抖动、面板布局、轴变换和
   SVG 序列化属于渲染布局，允许留在浏览器。
5. 文本分类列在前端矩阵缓存中保存为稳定整数代码 + 标签词典。只有整数代码进入现有
   DCM2 数值帧，24 字节头、列数契约和数值语义不变。图卡只用分类标签做颜色、形状、
   分面和图例映射；切换文件时分类词典与值数组一起刷新。
6. heatmap 仍是九种图型之一，增加 `correlation` / `field` 子模式，不新增第十种图型。
   多子图是同一绘图卡中的 panel 列表，最终从一个 SVG 根节点导出一次。

## 数值分析结果契约

`builtin:chart-analysis` 使用普通端口绑定和有限参数：

- `x`：可选单列；缺省时由调用者提供规则采样率。
- `y`：必选单列。
- `params.kind`：有限分析类型（回归、残差、区间、非线性模型、低通、去趋势）。
- `params.model` / `params.weighting` / `params` 中的数值仅由 UI 下拉和受限输入产生。
- 输出 `summary`：一行统计结果，列名是稳定语义 id。
- 输出 `series`：逐点结果，列名是稳定语义 id；拟合值、残差、两类区间和 QQ 坐标
  可按行对齐。无定义值写 `NaN`，绝不造 0。

渲染降采样只作用于 `series` 的显示副本；统计、拟合和诊断读取全量输入。

## 分类元数据

分类列不是字符串矩阵，也不是 DCM2 的隐藏扩展：

- 解析器第一次见到一列中的非数字标量时，保留原文本标签，并给每个唯一标签分配稳定序号。
- 数值数组保存该序号，`MatrixColumn` 的附加只读字段保存代码到标签的映射。
- 混合数值/文本列仍然是错误或显式缺失，而不是把任意文本静默映射成数字。
- 分类映射改变图形编码时不创建计算节点；它只改变 ECharts series 的图层语义。

## 约束与验收

- 新计算不得落入 `web/src/core/`、`web/src/charts/` 或图卡组件。
- OLS、WLS、置信带、预测带、4PL、指数、幂律、LOD/LOQ、低通和去趋势各自必须有后端
  ctest；前端只测试绑定、状态切换和几何输出。
- 绘图降采样测试必须证明尖峰不消失；小 `n` 测试必须证明每个原始点都进入 series。
- SVG 测试禁止参考线、阴影、标签、colorbar 或拼版退化成 `<image>`。
- 滤波结果只替换显示曲线。统计、拟合输入始终绑定原始 `y`，原始曲线可同时叠加。

## 不做

- 不新增表达式、函数卡、脚本、调度器或自动计算引擎。
- 不新增第十种图型、撤销栈、审计链、SPC/Cp/Cpk、判定结论或出版规范。
- 不修改端口身份、`params.columnContract`、DCM2 24 字节头、签名 id
  或 `/compute` 的既有同步语义。
