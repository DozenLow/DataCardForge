# 决策：单位感知阶梯与三档策略 —— P3「提示」与「公式输出单位」统一规划

- **日期**：2026-11-19（草案）→ 2026-11-19 方向已拍板
- **状态**：🧭 **方向已拍板，未实施**（L1 任务书待拆；本文不含代码改动）
- **标签**：`#单位 #函数卡 #量纲 #P3 #作用域`
- **上游**：[单位 v1](./2026-11-18-units-v1.md)（🔒：单位=派生元数据、数值永不自动改写、不做量纲代数）、
  [任务书 P3](../tasks/2026-11-18-units-v1.md)
- **结论**：P3 提示与公式输出单位是**同一量纲推断能力的两个消费方**，按推断阶梯 L1→L2→L3 分期；
  其上叠加**三档策略**（严格/自动换算/自由数值计算，默认严格）作为「拿知识怎么办」的_policy_层。
  机制（阶梯）只声明能证明的；策略决定冲突时问/换算/放行。保留 C+++TS 双引擎互抓单位；
  所有单位设置按 **卡 > 工作区 > 全局** 三层作用域，为「工作区作为工作区卡」的嵌套形态预留隔离。

## 一、机制：量纲推断阶梯（只声明能证明的）

| 级 | 推断能力 | 解锁 | 成本 | 契约 |
|---|---|---|---|---|
| L0=v1 | 无（输入派生元数据） | chip/确认/换算 | 已完成 | 无 |
| L1 | 直列操作数 + 用户显式断言 | 漂移提示、直列加法提示、公式显式输出单位 | 低 | additive：`warnings` 通道、`params.formulas[].unit?` |
| L2 | 安全白名单保单位继承（标「继承」） | `col*k`/MOV/EMA/ABS/AVG… 自动继承 | 中 | 白名单夹具钉死 |
| L3 | 完整量纲代数 | 复合量纲自动推导 | 高 | 动冻结契约；**留待真实需求** |

- L1 加法提示**只报能证明的**：`A+B` 两直列已知才比；嵌套不可解析则不报（不猜）。
- 显式输出单位=用户断言（`params.formulas[].unit?`），L1 **不做**「继承自源列」快捷项（留 L2）。
- L2 白名单必须可证明：`SIGN`(无量纲)/`SQRT`(^0.5)/`COUNT`/`SUM(A>5)` **不**继承；继承默认自动+标「继承」。
- L3 触发=出现「必须自动推导复合量纲」的真实需求且 L1/L2 不够；届时按 §四 镜像到 TS。

## 二、策略：三档（默认严格；全局默认 + 工作区/卡覆盖）

| 档 | 冲突/不一致时 | 数值 | 输出单位可信度 |
|---|---|---|---|
| **严格**（默认） | 手动拍板；**仅变化/冲突才提示**（打开时重校验，不每次全量确认） | 不改 | 声明=可证明/断言 |
| **自动换算** | 同量纲自动换算；歧义 token 用手动定义/全局预确认 | **opt-in 授权**，只产派生新表、源不动 | 标「已换算」 |
| **自由数值计算** | 不检查 | 不改 | 输出标**无单位/不可信**，下游不冒充可信 |

- **严格档防疲劳**：打开工作区时重新校验当前文件单位；只有「已解决单位现在冲突」或「文件单位签名变化」才提示，干净数据零打扰。
- **自动换算档**只在一**同量纲**内合法（N→kN）；跨量纲（力→质量）永远不可换算。它是用户 opt-in 的派生层改写，**源表永不改写**（保住 v1 冻结契约）。
- **自由数值计算**（原「游乐场」比喻，改正式名）：显著标识；其输出在轴/换算等下游视为无单位/不可信。
- **英制暂不支持**（盎司等），注册表保持公制；自动换算不处理英制。
- 优先级 **卡 > 工作区 > 全局**；持久化：全局=应用设置层（新建）、工作区=snapshot、卡=params。

## 三、手动物理常量/单位定义（工作区内嵌）

- 「g = 9.80665 m/s²」这类**多义 token 的物理含义/换算常量**由用户**手动指定**，并**嵌入工作区**（snapshot，同 `unitConfirmations`）。
- 例：`g` 可=克(mass) 或 标准重力加速度(9.80665 m/s²)；`N`/`G` 等多义同理。定义是工作区私有（不同项目约定不同），**不做全局**。
- **全局单位选项**（顶部）= 歧义 token 的**预确认默认**，与 v1「按签名逐次确认」合并：全局默认充当预确认，可被工作区定义/卡覆盖。
- 自动换算档消费这些定义把多义 token 落到确定量纲后再换算；严格档用它们消除歧义提示。

## 四、双引擎互抓单位（保留 oracle）

- 单位「算力便宜、出错贵」→ 保留 C+++TS 双引擎差分互抓（用户拍板）。
- 现有 xlayer 夹具只判数值+错误码；**扩展夹具加单位/量纲期望字段**，TS 参考引擎同步计算单位（additive 契约扩展）。
- L1/L2 不改数值语义，xlayer 数值夹具零改动；单位期望走新增字段/新夹具 `fixtures/units/`。
- L3 落地时按本条镜像代数到 TS（oracle 不退役）。

## 五、作用域设计（为「工作区作为工作区卡」预留）

未来一个工作区可被嵌入为另一工作区的「工作区卡」。单位相关变量/设置必须三层隔离，嵌入时**子工作区的 workspace/卡层随其 snapshot 携带，不并入父层**，全局层为应用级 fallback：

| 层 | 内容 | 持久化 | 嵌套行为 |
|---|---|---|---|
| 全局 | 默认策略档、歧义预确认默认、(语言) | 应用设置层（**新建**，现无 localStorage） | 父应用级，子继承为 fallback |
| 工作区 | 策略覆盖、手动常量定义、`unitConfirmations`、env/trust | snapshot | 子携带自有层，**不并入父** |
| 卡 | 策略覆盖、`formulas[].unit`、columnContract、smoothing | card.params | 随卡 |

- 解析顺序：卡覆盖 → 本工作区覆盖/定义 → 全局默认。嵌入上下文中子在**自己的** workspace 层内解析，父不污染子、子不泄漏父。
- `unitConfirmations` 按签名键控但存于各自 snapshot；嵌入时**禁止合并**子的确认进父 store（同表头不同含义会串）。
- trust/env 已工作区私有；嵌入不得自动信任子脚本，须在父上下文重新评估。

### 现有设置作用域审计（顺带检查）

- **无全局持久层**（无 localStorage）：现状一切持久都在 snapshot；「全局默认」需新建应用设置层。
- **locale/view 为会话态**（不持久）：与 README「布局持久化」表述有出入；新建全局层时一并决定 locale 是否入全局。
- **trust/env/unitConfirmations 已工作区私有**：嵌套友好，保持不合并即可。
- **卡级 params（smoothing/panel/contract）已卡私有**：嵌套友好。
