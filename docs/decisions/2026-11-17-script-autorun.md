# 决策：脚本卡的自动运行——clean 成功一次后与公式卡同频

- **日期**：2026-11-17
- **状态**：✅ 已实施（tri-state `autoRun`、脏节点触发、信任/环境门、run bar 开关）
- **标签**：`#前端 #脚本卡 #自动运行 #信任`
- **结论**：clean 运行**成功一次**之后，脚本卡的行为向公式卡看齐——定义改、输入变、重开
  工作区都会自动重算；debug 永不武装；自动运行**自成一个 200ms 之外的零延时触发**（骑在
  已有的脏节点信号上，不再加计时器）；每次自动运行前都过**工作区信任**与**环境戳一致**
  两道门；用户可以把开关关掉，关掉后手动运行也不会偷偷重新武装。
- **上游决策**：[Python 脚本卡](2026-11-15-python-script-card.md)（explicitCompute、
  两种运行、环境锁）、[工作区信任](2026-11-17-workspace-trust.md)（未确认的脚本不跑）、
  [操作结算](2026-11-17-operation-settle.md)（200ms 属于用户操作）

## 核心表述

> 第一次运行是用户亲手点的"我同意"；从此这张卡就像公式卡一样随数据变化重算。
> 自动运行不在计算节点里加防抖，也不绕过任何已有的门：信任、环境戳、阻塞、失败不重试。

## 背景（这一轮修的是什么）

脚本卡是 `explicitCompute` 签名：上游变了，后端只把节点标成 `dirty/UpstreamChanged`
并把子树 block 住，唯一入口是 `POST /compute`。于是：

| 现象 | 原因 |
|---|---|
| 上游文件换了，脚本不跑 | 没有触发点，节点一直停在"待重算" |
| 脚本跑完，下游也不更新 | 下游确实会更新（`computeNow` 评估整棵子树 + `refreshDependentsOf`），前提是先跑起来 |
| 重开工作区要重新点运行 | 运行状态不持久化，节点重建为"未请求" |

用户要求：只要成功跑过一次，之后（包括重开）就不需要手动运行。

## 决策内容

1. **tri-state `autoRun`**（持久化在卡片上，不进 `params`）：
   - `undefined`：从未武装——第一次运行必须手动点；
   - `true`：已武装——与公式卡同频；
   - `false`：用户显式关闭——之后即使手动运行成功也不自动重新武装（否则开关是装饰）。
2. **武装时刻**：clean 运行 `done` 且 `autoRun === undefined` 时置 `true`。debug 永不武装
   （它本来就不发布），失败的运行不武装。
3. **触发信号 = 脏节点**，不新增计时器。覆盖四类变化：
   - 定义推送（脚本/端口/输出名改动，经 200ms 全局结算后 PATCH）；
   - 输入重绑（换文件、切文件）；
   - 上游变化：后端把节点标脏并推 `dirty` 事件（**只有 `reason === "upstreamChanged"`**）；

   - 重开工作区：节点重建为 dirty。
   一个共享的 `maybeAutoRunScript(cardId)` 在这些路径上被调用；它二次检查节点确实为
   dirty、卡片仍武装、信任通过、环境一致、没有阻塞、没有在途运行。
   **定义/绑定变化只走推送路径**：后端对每次 PATCH 都会回推一个 dirty 事件
   （`notRequested`/`definitionChanged`），若事件路径也触发，就会形成「PATCH→事件→重算→
   PATCH」的自激循环（实测连续重算 6 次且停不下来）。事件路径只认 `upstreamChanged`，
   推送路径负责定义与绑定。
4. **不加自己的防抖**。200ms 结算属于用户操作；自动运行在结算之后直接发起，中间卡片由
   后端同步评估，不再等待。运行中再次收到触发时记一个"排队"标记，运行结束**无条件**再跑
   一次（不看节点是否仍为 dirty）：一次沉重的运行结束时会把节点写成 done，而在它计算期间
   到达的换文件/上游变化可能晚于这组数字——用 dirty 做二次判断会把这次变化静默丢掉。
   排队标记用后即清，因此不会循环。
5. **权限门在触发时与运行入口各判一次**：`scriptTrusted`（未确认的工作区脚本不自动跑）
   与 `workspaceEnvIsPinned`（环境戳不一致时保持手动，见脚本卡决策 §七）。运行入口
   （`runScriptCardNow`）自己也拒绝未信任的卡片，所以绕过 UI 的调用同样无效。
6. **失败不循环**：自动运行失败后节点是 `error`，不会自我重试；下一次真实变化再试。
   `runtimeMissing` 同理（等环境修好）。
7. **可见与可关**：run bar 上有一个"自动"开关（首次成功武装后出现，关掉后保持关闭）；
   卡片失败仍显示原有错误面板，不新增静默行为。
8. **重开即跑**：武装状态随工作区保存；恢复时节点重建为 dirty，自动运行随即发生，结果
   回到显示缓存、下游图表与链式卡照常刷新。这是"重开不需要手动运行"的实现。
9. **横幅如实**：`script.notice` 不再声称"均未自动执行"，改为"首次成功后才自动重跑，且
   先过工作区信任"。

## 不变量（改这块时不许破）

- 首次运行必须手点；debug 永不武装、永不发布。
- 自动运行不得绕过信任与环境两道门；未信任/环境不一致时保持手动。
- 自动运行不得引入逐卡计时器或防抖：触发信号是脏节点，结算只属于用户操作。
- 同一卡片同时最多一个运行；运行中收到的新变化在结束后复查，不叠加解释器。
- 失败不自动重试；关掉的自动开关不被手动成功重新打开。
- 自动运行不改变脚本能访问的路径集合（文件/目录信任是另一条待办）。

## 门禁

- `web/tests/ScriptCardStore.test.ts`（自动运行组）：clean 武装 / debug 不武装 /
  事件触发 / 定义改触发 / 未武装不跑 / 关闭后不跑 / 未信任不跑 / 环境不一致不跑 /
  失败只跑一次 / 保存重开后自动跑一次。
- `web/tests/ScriptCard.dom.test.tsx`：run bar 开关只在武装后出现、切换持久化。
- `web/scripts/smoke.mjs`：换文件后脚本自动重跑、下游图表更新（浏览器实弹）。
- 推送去重：相同的 `(params, bindings)` 不再 PATCH —— 既省一次往返，也避免把"重开时的
  重复推送"读成新的输入变化而多跑一次解释器。

## 修正（2026-11-17）：绿灯表示"数字到了"，图的曲线只在整列到齐后换

两个时序缺陷（真实 165k/161k 行表实测）：

1. **绿灯早到**。clean 运行在 `compute` 返回后就 `applyNodeSnapshot(done)`，而"完成"由 run
   状态决定；结果拉取（预览 + 整列）还没落地，灯已经是绿的，徽标还是旧尺寸——用户看到
   "没算完就绿了"。修正：clean 路径在**结果进入显示缓存之后**才把 run 标成 `done`，灯、
   徽标、下游三者同一刻翻面（实测同一采样点内 `computing/旧尺寸 → done/新尺寸`，此前有
   约 240 ms 的"绿灯 + 旧数字"窗口）。debug 不发布，因此不做这一步。
2. **图拿到没算完的矩阵**。函数卡的结果分两步落地：100 行预览（卡片表格用）与整列（图用）。
   `refreshDependentsOf` 对图卡依赖原先不看槽位是否完整，预览一落地就把 100 行交给图，
   曲线先画成 100 个点再跳到全量。修正：**图卡只从"该槽位已完整"的结果重新读取**，未完整
   时保留原曲线（陈旧而非截断），完整拉取落地的一次刷新再换。

不变量：灯/徽标/下游描述的都是"已经进入浏览器的那份结果"；图卡的曲线不为瞬时数据重画。

## 修正（2026-11-17，第二轮）：闸门重开时要补一次触发

自动运行的每一道门（工作区信任、环境戳、阻塞冻结）都是"关闭时**丢弃**触发"，这是冻结的
本意；但它意味着**门重开时没有任何东西记得还有活在等**。真实后果：打开一个来自文件的
工作区时，`loadSnapshot` 先把卡片推下去（节点变脏），信任查询随后才返回——落在这段窗口里的
触发被丢掉，于是"重开已武装的工作区会自动重算"对**所有来自文件的工作区**失效（内存里新建的
工作区不受影响，测试与手测都容易漏掉）。

修正：新增 `resumeAutoRuns()`——把所有"已武装且节点仍为 dirty"的脚本卡各触发一次，并在
**每一道门重开时**调用：信任查询返回、信任决策完成、逐个/批量确认、保存工作区（新哈希即
信任）、以及阻塞解除（`propagationFrozen` 由 true 变 false）。它只处理 dirty 节点，因此
不会重跑已经算完的卡，也不会与在途运行叠加（`scriptRunsInFlight` 仍在把关）。
