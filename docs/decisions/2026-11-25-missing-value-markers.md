# 决策：缺测记号按缺失读，不按文本读、也不猜数值

- **日期**：2026-11-25
- **状态**：🔒 已定稿
- **标签**：`#数据加载 #缺测值 #文本解析`
- **范围**：只规定「一个单元格里的记号算什么」，不改矩阵、协议、单位或任何计算口径。

## 结论

列分类时，下面这些记号与「空单元格」等价，进入矩阵的值是 `NaN`（表里显示 `—`）：

```
（空）  nan  +nan  -nan  NA  N/A  ND  <LOD  <LOQ  -  --  —  –
```

大小写不敏感。它们既不算数字、也不算文本，因此**不会**把一列数字变成「混合列」。

无穷大是数值，不是缺测。文件导入支持 `inf`、`Infinity`、`∞` 及其带符号写法（字母不区分大小写）；其中 `Infinity` 是 CSV 导出的写法，`∞` 是表格显示和复制的写法。

其余未识别的记号是文本，例如：

- `null` / `#N/A` 是电子表格的错误码，不是测量写法。
- 真正的分类标签（`control`、`treated`、批号、站点名……）。

数字列里出现上面这些**真文本**时，仍然拒绝整份文件——把标签悄悄抹成空白和把空白猜成数字一样坏。

顺带一条：首行检测也跟着改。首行只要「有数字、且每格都是数字或上述记号」，它就是数据行；`1, NA` 这种首行不再被当成表头吃掉。

## 为什么

一份 161903 行的导出把 807 个缺失样本写成字面 `nan`，Pos.4 / Pos.5 因此被判成「数字与文本混合」，整份文件打不开——而生产方想说的只是「这里没有数」。同类记号（`ND`、`<LOD`）在分析化学与仪器导出里同样常见。

`<LOD` / `<LOQ` 是**删失**数据：真值未知、且小于某个限。把限值的一半填进去，会让后面每个统计量都带一个编造出来的测量值；留成缺测虽然丢信息，但不会伪造信息。这符合本仓库一贯的口径：错误要么明说，要么留空，不给一个看起来合理的数。

## 边界与代价

- 分组列里恰好有一个标签叫 `NA` 或 `ND` 时，它会被读成缺测，该格失去标签。这是这条规则的已知代价；真要保留这种标签，得改列名或改记号。
- 目前没有「本列 N 个格按缺测处理」的提示。加载路径没有告警通道，加通道属于另一个决定；现在能看到的证据是表格里的 `—`。

## 不做什么

- 不做数值替换（`<LOD` 不填成 0 或限值的一半）。
- 不做逐文件的可配置缺测记号表（先把默认口径跑一段时间，需要再说）。
- 不动 `isNumeric` 的严格语法：它仍然是「像不像一个十进制数」的唯一判据。
