# 决策：工作区信任——按文件哈希记录、逐脚本确认、环境绑定

- **日期**：2026-11-17
- **状态**：✅ 已实施（后端信任存储与端点、前端文件哈希与信任面板、脚本卡锁定态）
- **标签**：`#前端 #后端 #安全 #脚本卡 #信任`
- **结论**：打开工作区文件时，浏览器对**文件字节**算 SHA-256，后端按这个哈希记录
  "用户确认过哪些脚本"；未命中的文件里的脚本**逐个确认**后才允许运行，用户逐个确认满
  3 个之后才允许一次信任其余；信任记录默认放在**可执行文件目录**（回退用户配置目录、
  再回退仅本会话），文件里只存**本机环境标识的哈希**，换机器/换环境即视为未信任。
- **上游决策**：[Python 脚本卡](2026-11-15-python-script-card.md)（runner 不是沙箱、脚本
  不是沙箱、`/api/script/check` 只 compile）、
  [端口锚点](2026-11-17-port-anchored-connections.md)（信任是权限，不是连线语义）

## 核心表述

> 一个工作区文件的字节哈希，就是"这份文件"的身份。用户确认过的脚本记在这个哈希下；
> 没确认过的脚本不跑——不手动跑，将来也不自动跑。记录是本机的、可撤销的、默认不写的，
> 换一台机器就重新问。信任是**许可**，不是触发器。

## 背景（这一轮修的是什么）

脚本卡是唯一会执行用户代码的卡，而 v1 的边界只有两条：runner 不是沙箱、请求要过 Origin
门。工作区文件可以来自任何地方（同事、下载、模板），而"打开文件"与"执行文件里的代码"
之间原本没有任何关卡：脚本可以手动点运行，一旦自动运行（下一阶段）落地，打开一个文件
就等于执行里面的全部脚本。信任记录是这两者之间的闸门，也是"自动运行"的前置条件。

## 决策内容

1. **信任的单位是文件哈希**。浏览器读取文件的 `ArrayBuffer`，用 WebCrypto 算 SHA-256；
   解析快照也用同一份字节（`TextDecoder`），所以"被信任的字节"与"被打开的字节"不可能
   不一致。后端从不读工作区文件，只把这个 64 位十六进制串当作不透明主键。
2. **记录的是脚本，不是整份文件**。一个哈希下存已确认的脚本卡片 id；未列出的脚本保持
   锁定。锁定卡片的运行/调试按钮禁用、快捷键拦截，store 的运行入口再判一次
   （`scriptTrusted`），所以没有第二条能绕过闸门的路径。
3. **批量确认有前提**。UI 不因"脚本多"就直接给"信任全部"；只有当用户**逐个确认满 3 个**
   之后，顶部面板才出现「信任其余全部」，且它一次只处理该文件里剩余的脚本。计数只按
   本次打开、本文件。
4. **首次运行询问是否持久化**。后端启动后第一次被问到时返回
   `persistence: "undecided"`；用户选「保留信任记录」才写盘，选「仅本次会话」则整个进程
   只用内存、不落任何文件，下次启动再问。写盘位置依次是**可执行文件所在目录**（便携发行
   包就放在程序旁边）、平台配置目录（`$XDG_CONFIG_HOME/datacardforge`、`%APPDATA%\
   DataCardForge`、`~/Library/Application Support/DataCardForge`），都不可写则退回
   仅会话并如实显示。写入是"临时文件 + rename"的原子替换，最多保留 100 个工作区记录。
5. **记录绑定本机环境**。记录文件里只有 `envId` 的哈希：
   FNV-1a 64 over `os + hostname + 可执行文件规范路径 + DC_PYRUNTIME`。环境不匹配时
   整份记录被忽略（`envChanged=true`），UI 明确说明"来自另一台机器/环境，需要重新确认"。
   这是**威慑**不是安全边界：能写记录文件的人也能改它；它拦的是"把信任文件连同工作区一起
   拷贝到另一台机器"。机器标识本身不落盘、不外发，也刻意不读系统 machine-id，避免隐私
   与跨平台 API 的额外面。
6. **保存是用户动作**。本应用保存出来的新文件哈希由前端登记为可信（用户刚刚亲手保存），
   所以重开自己存的文件不需要重新确认；这不会让外部文件变得可信。
7. **不可达不等于许可**。信任服务不可达时，状态是"未信任 + 仅本次会话"：脚本不会自动
   运行，手动确认后仍可运行。宁可多问一次，也不把"连不上"读成"同意"。
8. **不是沙箱**。信任只决定"要不要跑"，不限制脚本能访问什么。runner 仍是用户权限；
   文件/目录访问的**显式信任**是另一条待办（脚本卡决策 §九），两者不互相替代。

## 不变量（改这块时不许破）

- 信任的主键是**工作区文件字节的 SHA-256**，不是路径、不是标题、不是内容摘要。
- 未确认的脚本不执行：按钮、快捷键、store 入口、未来的自动运行，全部问同一个谓词。
- 批量信任只在该文件内、且用户已逐个确认满 3 个之后出现；不存在"因为脚本多所以直接全信"。
- 记录默认不写盘；用户没选「保留」之前，不产生任何信任文件。
- 记录文件只包含本机环境标识的哈希；环境不匹配的记录一律当未信任。
- 信任服务不可达 = 未信任（可手动确认后运行），绝不当成已信任。
- 信任是许可，不是触发器：记录一条信任不会启动任何计算。

## 门禁

- 后端 `ctest -R trust_store`：首次运行未决定、决定前拒绝记录、持久化后重载、撤销、
  环境不匹配、仅会话不落盘、100 条上限。
- 后端 `ctest -R origin_gate`：新端点仍在 Origin 门之后（既有用例覆盖路由层）。
- 前端 `workspaceTrust.test.ts`：字节哈希（与 Node `crypto` 对照）、三态信任谓词。
- 前端 `TrustPanel.dom.test.tsx`：首启询问与应用、逐脚本确认并记录、批量只在确认 3 个后
  出现、环境不匹配提示、信任服务不可达按未信任处理、无文件工作区不显示。
- 前端 `ScriptCard.dom.test.tsx`：锁定态按钮禁用 + 确认后解锁、store 直接运行被拒绝
  （`code: untrusted`）。

## 未决（下一轮）

- 文件/目录访问的显式信任（脚本卡决策 §九的待办）：信任工作区文件 ≠ 允许脚本读它的目录。
- 信任记录的 GUI 管理（列出、逐条撤销、导出）目前只有"撤销当前工作区"。
- 机器标识目前用 hostname+路径；若要更强的"换机检测"，可换成平台 machine-id（仅本地哈希）。
- 保存工作区时的自动登记目前由前端发起；若将来后端能读到文件路径，可改为后端登记。
