# 决策：数据卡可以换文件：换数据自动跟随，切文件仍显式重指向

- **日期**：2026-10-31
- **状态**：✅ 已实施（卡上「替换文件…」+ 拖放到卡；store `replaceCardSources`；下游自动跟随；后端同步释放）
- **标签**：`#前端 #数据卡 #模板复用 #依赖语义`
- **结论**：新增 `replaceCardSources`，换文件走 copy-on-write 新矩阵 id，本卡下游自动跟随；
  切文件（下拉）在 2026-11-17 修正为**同样是数据变更**——下游自动跟随，不再有重指向确认条。
- **上游决策**：[卡片数据结构 v2](2026-10-26-card-schema-v2.md)（函数卡输入冻结为显式矩阵）、
  [后端持有数据与计算](2026-10-17-backend-owns-compute.md)（计算权威在后端）

## 核心表述

> **换文件与切文件都是数据变更。** 换文件 = 给槽位一个新矩阵 id（copy-on-write）；切文件 =
> 这张卡从此代表下拉里选中的那份文件（旧文件仍留在卡里）。两者都让读这张卡的图卡与函数卡
> 立即改读新的矩阵并重算。

## 背景

数据卡从「打开数据文件…」或拖放创建之后，前端没有任何入口能改它显示的文件：

- 卡内只有文件选择框和锁；拖到卡上会冒泡到画布的 `onDrop`，照样新建一张卡；
- store 只有 `addMatrixCard`。保存的工作区（`loadSnapshot`）把矩阵一起写进 JSON，
  恢复出来的模板数据被冻结在文件里。

`保存工作区 → 打开工作区` 因此只能"看"，不能换一套新数据继续用——`FileIdentity` 的注释
（"传感器导出覆盖 `today.csv`"）描述了真实工作方式，但载入新版本后只能再建一张卡、手工重连。
这是「工作区模板无法复用」的具体形态。

## 选项与权衡

| 方案 | 结论 | 理由 |
|---|---|---|
| 显式重指向条（与切文件一致） | 否 | 模板复用的意图就是"换一套数据"，每张公式卡再点一次"应用"违背意图；且要为新动作复制一套提议机制 |
| 原地改写 `matrices[matrixId]` | 否 | 共享解析的别名会被写穿（改一张卡会改到另一张）；v2 的"冻结引用"因此名存实亡 |
| 新矩阵 + 本卡引用搬迁 | ✅ 采用 | 数据语义直白、别名安全、旧矩阵可回收；蓝图不必改 schema |

## 决策内容

1. 换文件按数据变更处理。新动作 `replaceCardSources(cardId, entries[, index])`：
   `index` 只换当前活动槽位（卡上按钮），不传则整组替换（拖放）。卡片 id、位置、z、`readOnly`、
   `inputs` 一律不动；快照仍是 `version: 2`，旧模板可继续打开。
2. copy-on-write，绝不原地改写。`addMatrixCard` 的身份缓存允许两张卡共用同一 `matrixId`
   （测试锁定）；原地写 `matrices[matrixId]` 会连带改掉另一张卡的数字。因此换文件总是给槽位分配
   新 id，并把本卡下游的引用搬到新 id 上。旧矩阵在「无人引用」时释放（本地 + `DELETE /api/matrices`）。
3. 下游自动跟随，且只跟随"同一个槽位"。
   - 图卡是视图：`refreshDependentsOf(cardId, retiredIds)` 重指向新的活动矩阵并按新数据重绘；
   - 公式卡的输入是本卡某一份文件的显式矩阵：把它改到对应槽位的新矩阵（整组替换按槽位序配对，
     新集合更短时未配对的槽位指向新集合第一个文件），注册完成后一次 PATCH 重算，不产生 `RepointOffer`；
   - 只改「本卡 → 本卡」的引用：别的卡的公式不会被顺带改掉。
4. 切文件不动。多文件卡的下拉仍是 `setActiveSource` + 黄色重指向条（v2 锁定）。两种操作语义不同，
   共用一套 UI 会让使用者分不清"换的是数据还是视角"。
5. 两个入口，一个语义。卡上「替换文件…」按钮（`pickFiles(false)`，换当前文件）与把文件拖到数据卡上
   （命中 `.card--matrix[data-card-id]`，整组替换）；拖到空白画布仍是新建卡。拖拽时命中的卡高亮，
   提示条改成「松开即可用这些文件替换「X」的数据」。
6. 解析失败整体中止。任何文件解析失败 ⇒ 逐条 toast，卡片原数据与连线保持不变（没有撤销栈，
   不允许"换了一半"）。
7. 后端不留孤儿。`closeAllCards` 此前只清浏览器，节点与上传的矩阵全留在后端；
   重开模板后旧节点仍读旧矩阵，反过来让换文件时的 `DELETE /api/matrices` 被拒（409）。
   现在关闭全部卡片会先删节点、再删上传矩阵；换文件释放旧矩阵放在「读者已重新绑定之后」
   （`waitForCardPushes`），避免 409。
8. 离线不静默。换文件在本地照常生效；注册失败时既有 banner 可见，重连时
   `ensureUploadedMatricesRegistered` 补注册并重推公式卡（此前"离线时新建的表"从不补注册）。

## 未来影响（已知限制，不是缺陷）

- 没有撤销栈：换错文件时把旧文件再换回来即可恢复（文件在磁盘上）；状态行与表头始终暴露当前文件。
- 图卡对已消失的列沿用既有规则（保留旧曲线），换文件时同样成立；形状漂移由
  `params.columnContract` 硬拦（红字断流 + 扩展/解除两条出路）。
- 本轮只做「换」：往多文件卡追加单个文件、删除某个文件仍未提供。
- 换文件不动 `readOnly`：文件表依旧默认只读，锁按钮语义不变。

## 修正（2026-11-17）：切文件也是数据变更，下游直接跟随

原先的「换文件=数据变更、切文件=视图变更」把下拉当成"换一份文件来看"，函数卡保持冻结，
靠黄色重指向条让用户确认。实际使用证明这条读法是错的：下拉**就是在切换这张卡持有什么
文件**，用户切完期望脚本/公式卡跟着算。旧模型下脚本卡尤其糟——报价只认旧的单端口
`source`，脚本卡（`in:N`）连确认入口都收不到：数据卡换了文件，脚本仍读旧的，节点一直是
`done`（绿灯），手动重算也只在旧输入上打转，看起来像"没反应"。

修正：

- `setActiveSource` 直接完成数据变更：把**所有读这张表的函数卡输入**改绑到新显示文件的矩阵
  （`repointReadersOf` 一次写入），随后逐卡 `syncFunctionCard` → PATCH → 公式卡重算、
  已武装的脚本自动重跑；未武装的脚本变脏等待手动运行。图卡原本就跟随（`refreshDependentsOf`）。
- **重指向报价流整体下线**：`RepointOffer`、`repointOffers`、`applyRepoint`/`dismissRepoint`、
  公式卡黄色条、脚本卡重指向条、`repoint-flash` 动画与 `formula.repoint.*` 文案全部删除。
- 旧文件仍是这张卡的 source（可切回），切回时读卡再跟着回到旧矩阵。
- 列数不匹配不再由"确认"拦截：跟随后由列数契约/后端错误可见地失败，与换文件同一套规则。
- 不变量：**任何时刻，读一张数据卡的函数卡都指向它当时显示的那份文件**；不再存在"绑定到
  非显示槽位"的合法状态（创建绑定显示文件，切换移动全部读卡）。

## 修正（2026-11-17）：图卡的列面板只列它读过的那几张卡

列面板（`ColumnDock`）原先遍历整个工作区，把所有数据卡的文件和所有函数卡的输出都列出来，
于是**任何一张图都能勾选任何一张卡的输出列**——包括脚本卡正在读的那张原始表。用户看到的是
"这张图能拿到所有卡片的输出矩阵列"，这违反数据流契约：图的 `inputs[]` 才是它与世界的连接，
列面板只是在这些连接内部选列。

修正：

- 列面板只列**该图有边的那几张卡**（由 `card.inputs[].target.cardId` 决定）发布的矩阵；
  同一张卡的多列/多个输出仍可自由切换（那是展示选择），别的卡不出现。
- 新增显式手势「**添加到已有图表 ▸ <图标题>**」：在数据卡列头右键、脚本/公式卡输出行右键
  的菜单里，把这一列作为新数据源接到指定的图上。它走 `commitChartConfig`，与任何图编辑
  一样做环检查并重导边——连接是**用户点出来的**，不是环境里默认可达的。
- 不变量：一张图能画的列 ⊆ 它已连接的卡所发布的矩阵；新增连接必须经过显式手势。
