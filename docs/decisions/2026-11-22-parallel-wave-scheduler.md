## 一、背景与实测依据

一波重算（矩阵变更 / 节点变更 / 显式计算触发）原先按拓扑序**串行**执行。用户提议「从变更点广度优先广播、卡片并行计算」；核实发现广度优先距离是**最短**路径，不等长汇聚点会读旧上游（已先修复为拓扑序）。在此基础上，三种调度方式用同一张七卡依赖图在真实后端各跑一遍（探针驱动调度、卡片计算真跑，脚本以睡眠代替重计算）：

| 调度 | 整波耗时 | 关键现象 |
|---|---|---|
| 串行（现状） | 4588 毫秒 | 七卡首尾相接 |
| 层屏障 | 3239 毫秒 | 己的输入戊 1010 毫秒已完成，却等无关慢卡乙到 2221 毫秒，空等 1212 毫秒 |
| 就绪队列 | 2725 毫秒 | 庚提前 1203 毫秒出结果；整波等于关键路径长度（物理下限） |

另有两组边界实测：八路独立脚本卡并发请求 5.47 秒→0.78 秒（七倍，子进程活在存储锁外）；一百个轻公式节点并发请求与串行一波同耗时（**存储单锁未拆，公式路径并行零收益**）。

## 二、决策

1. **波内调度用就绪队列，不用层屏障。** 节点的全部波内前驱完成即入就绪队列，有空闲工人立即开算，不等无关节点。层屏障的拖尾让用户的等待由最慢的无关卡决定，违背兜底原则（最坏情况没有墙）；就绪队列的代价（完成顺序不确定）由既有的定义版本守卫吸收，不是新负担。
2. **脚本子进程单开泳道。** 注册表级计数信号量封顶并发脚本子进程数（默认四，`DC_SCRIPT_LANE` 可调），对所有请求线程生效。重活（秒级、吃内存）与轻活（毫秒级公式）隔离：八张重脚本再也占不满全部工人、饿死公式卡。泳道判定走签名特征位 `childProcess`（`signature.h`），调度器不认卡种——下一个重能力声明同一特征位即得同一泳道。
3. **公式工人封顶八（`DC_FORMULA_LANE` 可调），调用线程也是工人。** 波内辅助线程按需创建、封顶八；触发请求的线程本身参与计算，线程创建失败时波仍能算完。单节点波直接串行，不付线程开销。
4. **排队可取消。** 脚本运行**先登记进 `runningPython_` 再等泳道槽位**，`/cancel` 对排队中的运行同样应答 true；等待谓词含取消标志，被取消的排队运行不启动解释器直接返回 `runCancelled`（回到「未请求」态，停止不是失败）。
5. **客户端契约零改动。** `recomputeSubtree` / `computeNow` / `onMatrixChanged` 仍在整波算完后返回；计算请求保持同步语义。完成事件按完成顺序发布（事件总线自有锁与序号），前端逐节点幂等消费，不受影响。
6. **完成即释放下游，错误还走老路。** 完成、出错、被取消都释放波内下游计数；出错生产者的下游照常运行、经 `gatherInputs` 继承 `upstreamError`——与串行语义一致。惰性签名（`explicitCompute`）在派发前单线程预处理：打脏并剪枝整棵下游子树（`prepareWave`），语义与旧串行遍历逐条对应。

## 三、锁与线程纪律

- 波状态锁（就绪队列 / 入度 / 工人计数）与注册表锁**从不嵌套**：工人取节点时持波锁、算节点时持注册表短锁，二者先后不相交。
- 泳道锁与注册表锁的唯一嵌套方向是**泳道→注册表**（排队取消路径：先醒在泳道等待里，再摘登记）；反向不存在。
- 注册表→存储的既有锁序不变。工人线程不让任何异常逃逸（外层兜底捕获）——畸形请求压测的教训：逃逸异常 = `std::terminate` = 整进程死。
- 波结束条件（未完成计数归零）与「归零后不再派生线程」在同一临界区证明，调用线程汇合所有工人不会死锁。

## 四、已知边界（阶段二开板，不在本次范围）

1. **存储单锁未拆**：公式路径的并行收益被 `MatrixStore` 全局锁封顶（实测零收益）。拆锁（分片或快照租借）是阶段二主体，届时并发下的第 95 百分位耗时进性能门禁（性能决策早已写明「开始多线程就要加」）。
2. **每波创建线程**：辅助线程随波生灭；常驻池是阶段二优化（当前每波至多八线程，开销可接受）。
3. **`onMatrixChanged` 逐直接读者起波**：重叠子树会重算多次（既有行为）；多根合并成一波留阶段二。
4. **跨波同节点重叠**：两个请求线程的波可能同时算同一节点（既有行为，定义版本守卫挡定义变更，数据变更竞态由前端 200 毫秒结算合并兜底）；节点级在飞去重留阶段二。
5. **波级预算 / 取消**：并发上限即预算；取消沿用节点级 `/cancel`（契约冻结）。整波一键停止留阶段二。

## 六、被否掉的替代

- **层屏障**：实测拖尾 1212 毫秒，最坏等待由无关慢卡决定——否。
- **重轻活混用一池**：重脚本占满工人、毫秒级公式卡排队数秒——否。
- **阶段一常驻线程池**：关机 / 多波共享 / 生命周期复杂度超出本次收益——延后。
- **广度优先距离分层**：最短路径 ≠ 求值序，会复现读旧数 bug——否（前置修复已消灭）。
